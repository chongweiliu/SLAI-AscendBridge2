# 驱动与固件维护手册

## 变更前

1. 从目标硬件和操作系统对应的华为官方兼容矩阵确定 driver、firmware、CANN、内核和
   torch-npu 组合；不凭其他节点的包名猜版本。
2. 校验安装包来源、签名/哈希、芯片系列、CPU 架构和包数量，保存现有版本、安装日志和
   官方回滚包。检查 DKMS/内核 headers、磁盘空间、root 权限和维护窗口。
3. 停止并确认目标节点上的 NPU 作业已排空。多机集群一次只处理批准范围内的节点，明确
   是否需要重启和服务中断。
4. 向用户展示计划、命令、影响、回滚和验证；取得本次节点级变更的明确确认。

## 获授权后

只使用对应官方 `.run` 包/仓库说明支持的参数。一般按目标版本文档规定的驱动与固件顺序
执行，不把某一版本的顺序强加到所有版本；禁止脚本静默创建用户、改软件源、自动 reboot
或在失败后继续下一包。每一步保留退出码和安装日志，出现版本/设备/内核不匹配立即停止。

## 变更后

重启仅在用户授权的维护窗口执行。启动后验证内核模块、`npu-smi` 版本与 health、所有设备
可见性、错误码和日志；再验证 CANN/torch-npu 最小 op。多机逐节点比对版本与健康状态，
随后运行 HCCL 快速正确性测试。最后才恢复 vLLM 单卡、目标 TP 和 PD 服务。

如果验证失败，按预先记录的官方回滚流程处理，不混装另一个未审批版本；报告节点状态和
是否仍需隔离。
